# Roadmap: SendPulse for Gmail v2

Мета — робоче розширення для Chrome (Manifest V3), яке з будь-якого листа в Gmail
дає за кілька кліків додати співрозмовника в SendPulse, збагатити контакт даними
і бачити його статус у SendPulse.

## Архітектура

```
┌──────────────── Gmail tab ────────────────┐      ┌──── Service worker (background) ────┐
│ content script                            │      │ SendPulse client (fetch, async)      │
│  ├─ GmailAdapter (InboxSDK)               │ msg  │  ├─ auth: client_credentials,        │
│  │   └─ поточний лист → учасники, підпис  │◄────►│  │   автооновлення токена            │
│  └─ Sidebar UI (Vue 3)                    │      │  ├─ addressbooks / emails / CRM      │
│      ├─ картка контакту                   │      │  └─ chrome.storage (токен, ключі)    │
│      ├─ вибір книги + змінні              │      │ Enrichment providers                 │
│      └─ статус у SendPulse                │      │  └─ (опційно) зовнішній API з ключем  │
└───────────────────────────────────────────┘      └──────────────────────────────────────┘
Options page (Vue 3): логін SendPulse, налаштування, мапінг змінних, ключі провайдерів
```

Принципи:

- **Усі мережеві запити — тільки з service worker.** Content script не бачить токенів;
  секрети — у `chrome.storage.local`, не в `localStorage` сторінки Gmail.
- **Gmail DOM — тільки через один адаптер** (`GmailAdapter`). Коли Gmail зміниться,
  правиться одне місце. Базова реалізація — InboxSDK.
- **Збагачення контакту — через інтерфейс `ContactSource`.** Кожне джерело повертає
  частковий профіль (`firstName`, `lastName`, `phone`, `company`, `title`, `linkedinUrl`…),
  результати зливаються з пріоритетами. Нове джерело = новий клас, UI не змінюється.
- **Призначення — через інтерфейс `Destination`** (адресна книга, CRM-контакт, угода),
  щоб додати CRM без переписування UI.
- **Без скрейпінгу соцмереж із cookie користувача** (Facebook, LinkedIn): порушує їхні
  правила й правила Chrome Web Store, і ламається без попередження.

## Джерела даних про контакт (`ContactSource`)

| Джерело                                                                                      | Що дає                                                                                         | Статус              |
| -------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------- | ------------------- |
| Заголовок листа `"Ім'я Прізвище" <email>`                                                    | ім'я, прізвище                                                                                 | базове, обовʼязкове |
| Підпис у тілі листа (парсер)                                                                 | телефон, компанія, посада, сайт, посилання LinkedIn                                            | v2                  |
| Уже наявні дані в SendPulse                                                                  | змінні контакту, книги, статус                                                                 | базове              |
| LinkedIn                                                                                     | кнопка «Знайти в LinkedIn» (відкриває пошук у новій вкладці) + збереження URL профілю у змінну | v2                  |
| Зовнішній enrichment API за ключем користувача (Apollo / Hunter / People Data Labs — обрати) | компанія, посада, LinkedIn                                                                     | опційно, v3         |

## Етапи

### Етап 0. Безпека (зараз)

- [x] Прибрати з коду Facebook-токен, cookie і ключі SendPulse
- [ ] **Власник:** відкликати ключі SendPulse API (з `test/responses/mock.ts`) і завершити сесії Facebook
- [ ] Рішення: чи переписувати історію git (`git filter-repo`), щоб секрети зникли зі старих комітів

### Етап 1. Новий каркас

- [x] Vite + Vue 3 + TypeScript 6 + CRXJS, Manifest V3
- [x] ESLint + Prettier, Vitest, `.gitignore`, `.nvmrc`
- [x] GitHub Actions: lint + test + build zip
- [x] Старий код видалити (лишається в історії git)
- [ ] Перевірити вручну: завантажити `dist/` у Chrome, побачити в консолі Gmail `[SendPulse] extension v2.0.0 loaded`

### Етап 2. Ядро: SendPulse-клієнт у service worker

- [x] `fetch` + async/await, типізовані відповіді (`src/background/sendpulse.ts`)
- [x] Логін client_credentials; credentials у `chrome.storage.local`, токен у `chrome.storage.session`;
      тихе оновлення токена за хвилину до кінця строку і повтор запиту один раз при 401
- [x] Типізований RPC content/options ↔ background (`src/shared/messages.ts`, `src/background/router.ts`)
- [x] Тести клієнта й роутера на моках `fetch`
- [x] Звірено з документацією: `emails` передається JSON-масивом, PHP-serialize не потрібен
- [x] Мінімальна форма логіну в options page (для ручної перевірки)
- [ ] Перевірити вручну з реальними ключами: логін і список адресних книг на сторінці налаштувань

### Етап 3. Інтеграція з Gmail

- [x] Адаптер Gmail на InboxSDK (`src/content/gmail.ts`); для розробки App ID не потрібен
- [x] Панель «SendPulse» у правому сайдбарі відкритого листа зі списком учасників (from/to/cc, без вас)
- [x] Ім'я та прізвище з заголовків листа (`src/content/participants.ts`, з тестами)
- [x] Для кожного учасника — чи є він уже в SendPulse і в скількох книгах
- [ ] **Власник:** зареєструвати App ID на inboxsdk.com/register і покласти в `.env` (`VITE_INBOXSDK_APP_ID`) — потрібно до публікації
- [ ] Перевірити вручну в Gmail: панель з'являється, учасники й статуси правильні

### Етап 4. Основний UI

- [x] Панель: у яких книгах контакт уже є (за назвами), галочки, редагування імені й прізвища

- [x] Автоматичний розклад імені по змінних книги (`firstName`/`lastName`/`name`/`Ім'я`… — `src/shared/fields.ts`)
